# 코드 뼈대 — 계약에서 코드가 먼저 쓰고, 생성기는 몸통만

> 상태: 2026-11-11 [확정: 2026-11-11 사용자 — "문서로 남기고 React 부터 진행"]. 결정 표기는 온톨로지 레포와 같다.
> 관련: `docs/design/spec-to-code.md`(생성 파이프라인), `docs/design/starter-templates.md`(템플릿), 지원자 README 의 '시작 코드' 절
> (`starter/code_map.py`, PR #107).

## 1. 왜

이슈 #102: 생성기 다섯(시작 코드·흔한 구현·허용 구현·숨은·공개 테스트)이 서로를 보지 않고 각자 짐작해, 계약이 정하지 않은 곳마다 어긋난다.
2026-11-11 알파에서 본 이름·모양 짐작:

- 숨은 테스트 `toItem(body, id: number)` — 하네스는 `id: string`, 공개 테스트·시작 코드도 같은 실수 (컴파일 수리 3건)
- 허용 구현이 계약 타입 대신 `PendingNote` 를 지어 `PostApiInspectionNotesBody` 자리에 넘김 (TS2345)
- 흔한 구현·d1 이 `unknown` 을 화면에 그림 (TS2322)
- 시작 코드 주석 `TODO: … localStorage 대기열, online 이벤트 동기화를 구현한다` — 숨은 요구의 해법이 지원자 화면(코드)에 샘

계약 타입(`src/api/contract-types.ts`)을 코드가 쓰고 잠근 뒤로 응답 모양 짐작이 사라졌다. 같은 방식을 **계약이 이미 공개한 구조 전체**로 넓힌다.

## 2. 뼈대에 넣는 것 / 넣지 않는 것 (React)

| 파일 | 내용 | 잠금 |
|---|---|---|
| `src/api/contract-types.ts` | 계약 타입 (지금과 같음) | **잠김** — 생성기가 쓰면 버리고 코드 판 |
| `src/api/endpoints.ts` | API 마다 호출 함수 하나 — 이름은 하네스 도우미와 같은 규칙(`method_name`: `POST /api/inspection-notes` → `postApiInspectionNotes`), 매개변수는 경로 변수(문자열) → 요청 본문(`<Api>Body`) → 쿼리 → `init?: RequestInit`, 돌려주는 값 `Promise<<Api>Ok>`. 기본 몸통: `fetch` 한 번, 2xx 가 아니면 `ApiError(status, 본문)` | 잠그지 않음 — **이름·시그니처 유지** |
| `src/pages/<화면>Page.tsx` | 화면마다 컴포넌트 껍데기 (계약 화면 id·경로·요약을 주석으로) | 잠그지 않음 — 이름 유지 |
| `src/App.tsx` | `BrowserRouter` + 화면 경로 → 컴포넌트 라우트 + `QueryClientProvider`(마운트마다 새 `QueryClient` — 테스트 사이 캐시가 남지 않게) | 잠그지 않음 — 라우트 유지 |

- **몸통은 비우거나 기본만 둔다.** 숨은 요구의 함정은 몸통에 있다 (토큰 갱신 — 요청 계층의 갱신 묶기, 응답 순서 — 지난 응답 무시, 오프라인 — 대기열).
  API 호출 함수의 기본 몸통은 `fetch` 한 번뿐이다 — 재시도·캐시·갱신·중복 제거·취소 같은 장치를 넣지 않는다. 취소·헤더는 `init` 으로 부르는 쪽이 정한다.
- **잠그는 것은 계약 타입뿐이다.** 요청 계층이 과제인 재료(토큰 갱신)는 지원자가 `endpoints.ts` 안을 고친다 — 대신 이름·시그니처는 유지한다.
- 주석은 계약 문장(API 요약·화면 요약)만 코드가 쓴다 — 할 일·해법을 쓰지 않는다.

## 3. 생성기의 일

| 생성기 | 뼈대 위에서 |
|---|---|
| 시작 코드 | 기존 기능의 몸통과 화면 요소(계약 test id)를 채운다. 뼈대 파일을 고쳐도 되지만 이름·시그니처·라우트는 유지 |
| 흔한 구현·허용 구현 | 같은 뼈대의 몸통을 설계대로 채운다. 도우미 파일을 더해도 된다 |
| 숨은·공개 테스트 | 계약만 본다 (그대로) |
| README | 시작 코드에서 이름을 뽑는다 (그대로) — 뼈대에서 온 파일은 '이름·시그니처를 유지한다' |

안내는 프롬프트 새 판이 아니라 **코드가 쓰는 입력 글**에 붙인다 (`template_files` 에 뼈대 파일과 규칙) — 템플릿이 뼈대를 켰을 때만.

## 4. 지키는 장치

1. 정적 검사 `_skeleton_kept`(시작 코드·참조 구현): 뼈대 파일이 있고, `endpoints.ts` 의 export 함수 이름·매개변수 목록이 뼈대와 같고,
   화면 컴포넌트가 그 이름으로 export default 되고, `App.tsx` 에 뼈대 라우트(경로 → 컴포넌트)가 모두 있다. 아니면 다시 요청.
2. 잠금 — 계약 타입은 지금처럼 코드 판.
3. README 대조 — README 의 이름이 실제 코드에 있다 (PR #107).
4. 생성기가 뼈대 파일을 빠뜨리면 코드가 뼈대 판을 넣는다 (시작 코드).

## 6. Java (Spring Boot) [확정: 2026-11-11 사용자 — "백엔드도 구현"]

| 파일 (`com.example.service.api`) | 내용 |
|---|---|
| `ContractController.java` | 계약 API 매핑 전부 한곳 — 메서드 이름은 React 와 같은 `method_name`, 매개변수는 경로 변수 → `body` → 쿼리 → 요청 헤더. 몸통은 `service.<같은 이름>(…)` 로 넘기기만 |
| `ContractService.java` | 같은 이름·매개변수의 처리 메서드, 몸통은 `UnsupportedOperationException` — 생성기가 채운다 (리포지토리는 생성자로 받아 더한다) |
| `<Api>Request.java` | 요청 본문 record — 계약 칸 그대로. 날짜·시각·enum 칸은 `String` 으로 받아 구현이 해석 (Instant·LocalDateTime 짐작을 막는다) |

- 돌려주는 값은 `ResponseEntity<?>` — 응답 DTO·엔티티·리포지토리·시드 SQL 은 생성기 몫이다 (테이블 이름·외래 키·시드 대조는 기존 검사).
- 경로 변수 타입은 같은 이름의 엔티티 칸 타입, 없으면 `…Id`·`id` 는 `Long`, 나머지 `String`.
- 정적 검사: 두 클래스의 메서드 이름·매개변수, 컨트롤러 매핑, **다른 컨트롤러가 계약 경로를 다시 매핑하지 않음** (같은 경로 두 매핑이면 기동 실패).
- 확인: 실제 백엔드 계약 3개(여신 상태 변경 ×2, 게시판 N+1)로 만든 뼈대가 v2 템플릿에서 Gradle 컴파일 통과.

## 7. 위험

- 설계를 좁힐 수 있다 — 허용 설계가 새 파일·도우미를 더하는 것은 막지 않지만 뼈대 함수의 시그니처를 바꿔야 하는 설계는 막힌다.
  재료마다 허용 설계를 대조해 그런 설계가 있으면 그 재료는 뼈대 함수를 시그니처 고정에서 뺀다 [미정].
- 템플릿 새 판 — 판정 이미지 해시가 바뀐다. 기존 빌드와 섞이지 않게 판을 고정한다.
