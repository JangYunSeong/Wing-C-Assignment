v4 주의 (v2 주의 이어짐)
- 기능형 기본값(`FEATURE_TASK_DEFAULT`)은 계속 꺼 둔다 — 승격은 승인자가 기능형을 지정할 때 쓰는 프롬프트만 바꾼다.
- 표본은 직군별 1건·1회. 운영 모델(qwen3.8-flash)로는 가상 공고 스모크 1건뿐 (첫 답 2건 위반 — 자료 제목 "비교", 원 사례 수치 기억 복사 → 재요청 뒤 통과, $0.023)
  — 기본값을 켜기 전 운영 모델로 dev·test 평가가 필요하다 (설계 §9).
- 기능형 재료(공개 사례 feature 블록)는 사람 검토 전(`reviewed: false`) — 생성된 명세에 표시가 남는다.
- 본문을 읽어 보면 검사가 못 잡는 문제 두 가지: ① 상황 글이 운영 조건을 바꿔 말함 (프론트 "여러 창이나 탭으로 동시에",
  데이터 엔지니어 "항목 수가 많아지면 … 오류"·"신규 데이터베이스 추가 예정", ML "실시간 경로에 구현해 넣을 예정") — 재료의 금지어 목록으로는 안 걸림,
  ② match_terms 가 공개 글에 이미 있는 넓은 말이라 (ML 9/12, 데이터 엔지니어 7/17) 일반 질문에도 구체 답이 나감.
  → 코드 검사로 막음 [확정: 2026-11-06 사용자] — 재료 `trigger_terms` 로 상황·공개 요구 검사(재요청), 공개 글의 매칭 낱말은 지움(재요청 없음).
  검사 넣은 뒤 같은 5개 공고 (`…-feature-subs-gpt41-v4-trigger`, 2026-11-06): 운영 조건 표현이 첫 답 4/5 에서 걸려 재요청으로 고쳐짐,
  최종 통과 3/5 (DBA 구현 방법 "트랜잭션", ML 2단계 자료 역할), 비용 $0.347 (ML 스키마 위반 재시도 1회 포함). 남은 것 — 목록 밖 바꿔 쓰기
