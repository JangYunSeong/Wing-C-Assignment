v6 주의
- 기능형 기본값(`FEATURE_TASK_DEFAULT`)은 계속 꺼 둔다 — 승격은 승인자가 기능형을 지정할 때 쓰는 프롬프트만 바꾼다.
- 표본은 직군별 1건·1회, gpt-4.1 로만 비교했다 (운영 모델 qwen 평가는 2026-11-06 사용자 요청으로 중단). 기본값을 켜기 전 운영 모델로 dev·test 평가가 필요하다 (설계 §9).
- 기능형 재료는 사람 검토 전(`reviewed: false`).
- 남은 실패·한계: 프론트 핵심 자료 본문의 판정 낱말("missing"·"mismatch"), 데이터 엔지니어 2단계 자료 제목에 "권한 변경"(재요청 뒤에도 남음),
  단어 목록 밖 바꿔 쓰기(ML "요청마다 실시간으로 피처 값을 계산") — LLM 판정(PR-4) 몫. DBA 역량·재료 불일치, 프론트 기술 환경 Java [미정].
- 단서 모호한 답이 핵심 자료를 가리키므로 일반 질문만으로도 어느 자료가 핵심인지 알 수 있다 (사용자 결정 (B) 의 대가 — 질문 한도 2개).

버전별 기록 (v3·v5 는 CURRENT 가 된 적 없음)
- **v3** — v2 + 추가 요구 두 층 답(answer_hint / answer + match_terms). 사용자 결정 2026-11-06 ("보낼 때 바꾸지 않고 생성 단계에서 두 층, 함께 승인").
- **v5** — v4 + 단서 추가 요구의 모호한 답을 "볼 곳"으로 (사용자 결정 2026-11-06 (B)): 생성 모델은 단서 자료(1단계 자료 title, `hint_source`)만 지목하고
  모호한 답 문장은 코드가 만든다 ("'<제목>' 자료에서 확인할 수 있습니다.", `fill_from_seed_v5`). 지목한 자료가 1단계에 없거나 방해 자료면 재요청.
  같이 들어간 코드 검사(모든 버전에 적용): 1단계 자료 제목의 운영 조건 표현(재료 자료 종류 이름의 말은 허용), 매칭 낱말 두 글자 이하 일반어 지움.
  5개 직군 비교 (2026-11-06, 같은 공고, premium gpt-4.1, `…-feature-subs-gpt41-v5`): 단서 모호한 답의 운영 조건 표현 v4+검사 4/10 → v5 0/11 (모두 "볼 곳"),
  구체 답 조건으로 쓸 매칭 낱말 단서당 v4 2.1개(일반어 빼고) → v5 3.9개 (두 단어·영문 표기), 자료 제목 운영 조건 1 → 0, 단서 자료는 모두 핵심 자료.
  최종 통과 v4+검사 3/5 → v5 2/5, 첫 답 0/5, 비용 $0.347 → $0.362 (스키마 위반 재시도 3회 — 추가 요구 answer 빠짐 등).

  데이터 엔지니어·ML 은 재요청 뒤에도 상황 글의 운영 조건 표현이 남음, ML 은 단서 아닌 추가 요구의 모호한 답 = 구체 답.
  운영 모델(qwen) 평가는 사용자 요청으로 중단 (2026-11-06 "gpt로만 해도 돼"). 승격 보류.
