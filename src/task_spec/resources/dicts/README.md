# 가명화 사전 (공개 목록 — 지원자 데이터 아님)

형식: 한 줄에 한 실체. `대표표기|별칭|별칭…` — 같은 줄의 표기는 같은 토큰을 받는다. `#` 은 주석.
목록은 완전하지 않다. 사전에 없는 학교·회사는 접미어 규칙(`~대학교`, `주식회사 ~`, `(주)`)과
라벨 규칙(`학교:` 등)으로 보완한다. 누락이 보이면 여기 추가한다 (공개 명칭만).

| 파일 | 범주 |
|---|---|
| universities.txt | SCHOOL |
| companies.txt | ORG |
| courses.txt | COURSE |
| surnames.txt | 사람 이름 판정용 성씨 |
| tech_terms.txt | 치환하지 않을 기술·도구 용어 (이름 오탐 방지) |
| org_generic_stems.txt | 업종 접미어 앞에 와도 회사가 아닌 일반어 (회사 오탐 방지 — "인터넷은행", "신용카드") |
| surnames_roman.txt | 성씨 로마자 표기 (영문 이름 판정) |
| en_words.txt | 로마자 이름 변형과 겹칠 수 있는 영어·기술 단어 (이름만 표기 전파 방지, 공개 공고에서 추출) |
| public_vocab.txt | 공개 어휘 — 공개 채용 공고·NCS 수행준거의 명사·영문 단어 (약한 문맥 값의 전파 여부, 생성 파일) |

규칙
- 일반어와 겹치는 짧은 별칭(이대·외대·소마·당근·라인 등)은 넣지 않는다 — "이대로", "파이프라인" 오탐.
- `!` 접두 줄은 같은 줄에 기간이나 재직·근무·인턴·입사·퇴사 표현이 있을 때만 치환한다
  (구글·오라클처럼 회사명이자 도구명인 경우).
- 별칭 뒤에 허용 접미(학교+생, 회사+대문자 약어·클론·클라우드·Clone·Cloud)가 붙어도 같은 실체로 치환한다
  (`dictionaries.SUFFIX_ATTACHED`, 2026-11-04). 허용 목록 밖 접미("카카오톡")는 다른 단어로 본다.
- `tech_terms.txt` 의 "성씨로 시작하는 기술·측정 명사" 줄은 Kiwi 가 문맥에 따라 이름으로 잡던 것 중 자주 나오는 것만.
  이름에 쓰이지 않는 일부 외래어 음절만 `detectors._FOREIGN_SYLLABLES` 규칙이 막는다 — 이름에 있을 법한 음절로 거르면
  실제 이름이 새므로, 새 오탐 명사는 규칙을 넓히지 말고 이 목록에 단어를 더한다.
- `org_generic_stems.txt` (2026-11-04 2차): 사전에 없는 회사를 업종 접미어(은행·카드·게임즈·랩스 …)로 잡을 때,
  접미어 앞부분이 이 목록의 단어와 같으면 회사로 보지 않는다. 회사 값은 같은 run 전체로 전파되므로
  일반어를 잡으면 문서 곳곳이 지워진다 — 새 오탐은 규칙을 넓히지 말고 이 목록에 단어를 더한다.
  어간 **전체**가 목록 단어 하나일 때만 뺀다 (끝말 비교 안 함 — "…국민카드" 같은 회사 모양이 숨는다). 고유명사로도 쓰이는
  어간(가상·국민·기업·투자·모바일)은 넣지 않는다.
- `tech_terms.txt` 끝의 영문 기술·도구 단어는 대소문자 무시로 영문 회사·영문 이름 후보에서 뺀다 ("Spring Boot", 2차).
- `public_vocab.txt` 는 손으로 고치지 않는다. 온톨로지 산출물이 바뀌면 다시 만든다:
  `uv run python -m eval.pseudonymize.build_public_vocab --sqlite <ontology.sqlite>`. 입력은 공개 데이터(공고 문장·NCS 수행준거)뿐이고,
  회사 사전·온톨로지 회사 표의 이름, 10번 미만 나온 Kiwi 사전 고유명사, 공고 문장의 이름 모양 단어(NCS 는 거르지 않음),
  드문 이름 모양 두 음절 단어(7번 미만), 도메인 모양 영문은 빠진다.
  머리줄에 온톨로지·Kiwi 버전을 적는다. 쓰임: 약한 문맥 값의 전파 범위(공개 어휘면 고용 문맥·그 자리만), 이름만 영문 표기 불용어(영문 3자 이상),
  이름 모양 보조 규칙의 오탐 거르기, 성 뺀 한글 이름 표기의 범위.
