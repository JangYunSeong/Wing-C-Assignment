### 2026-11-04 보강 (평가: `eval/pseudonymize/samples/stress_dev.jsonl` — 지금 평가로 안 보이던 경우)

- **링크**: 라벨 뒤라도 버전("v1.2.3")·파일명("main.py")·GitHub 기능·흔한 단어(README·Issues·Actions·Python …)는 핸들이 아니다.

- **Kiwi 이름 후보 오탐** ("임베딩 유사도 검색" → `[PERSON]`): **재현율(누출 방지)이 우선**이라 문맥 규칙은 쓰지 않는다.
  오탐 명사는 `tech_terms.txt` **단어 목록**으로 막는다 (유사도·기본값·주피터·마운트·인코딩·최댓값 …). 규칙은 하나 —
  이름에 쓰이지 않는 외래어 음절(`_FOREIGN_SYLLABLES`: 튜·뷰·큐·셋 …)이 있으면 명사, 바로 뒤에 조사가 붙으면 면제.
  이름에 있을 법한 음절(량·률·스·크·트·플·값)은 넣지 않는다 (privacy-auditor 1차 H2: "강동량" 류가 모두 빠졌다).
  "뒤에 기술어가 오면 명사" 같은 문맥 규칙은 "김민재 값 비교" 같은 일상 문장의 이름을 놓쳐 지웠다 (2차 H-new1: 60건 중 60건 노출).
  Kiwi 신뢰도·사전 밖 여부로 거르지 않는다 (이름 재현율 붕괴).
- **전파는 바꾸지 않는다**: Kiwi 로 잡힌 값도 사전 값처럼 같은 run 의 합성어 안까지 치환한다 ("개발자윤하람" → "개발자[PERSON_1]").
  경계로 제한하면 이름이 조용히 새고(privacy-auditor H1: 169명 중 158명), 누락 검사만 경계 없이 세면 같은 경우 실행이 멈춘다.
  명사 오탐의 합성어 손상("코사인유사도")은 원천(위 규칙·단어 목록)에서 막는다.
- **붙은 표기**: 사전 실체 + 허용 접미 (`SUFFIX_ATTACHED` — 학교+생, 회사+대문자 약어·클론·클라우드·Clone·Cloud).
  별칭만 치환하고 접미는 남긴다 ("[ORG_1]DS"). 허용 목록 밖("카카오톡")은 그대로.
- **호칭**: 이름 뒤 "팀원·동료" 추가 — 앞 단어가 흔한 관형형 단어 목록(`_PEER_MODIFIERS`: 함께한·참여한·합류한·새로운·기존 …)이면 이름으로 보지 않음
  ("함께한 동료", "새로 합류한 팀원"). 끝음절로 거르면 실제 이름(정우한·최가난)과 겹친다. '학생·멘티' 와 이름 앞 호칭 추가는 일반 명사 오탐("학생 정보를", "장학금 학생")이라 넣지 않음.
- `!하이브` — Apache Hive(하이브)와 겹쳐 재직 맥락에서만.

    기술 외래어 "온프레미스"). 그 칸은 항상 바꾸고, 본문은 "X에서 3년간·근무·재직·일하·개발", "X에 입사·합류", "X 인턴·재직 중",
    "(전) X" 만 — "생산 중앙", "중앙 서버"는 남는다. 누락 검사도 같은 고용 문맥 정규식으로 센다.
  - **none** (그 자리만): ① 이름 라벨 옆 표 열 이름과 같은 공개 어휘 값("이름⇥성과") ② 이름 부분이 공개 어휘뿐인 교육 과정
    ("사내 교육 과정") ③ 머리줄의 이름 모양 공개어("경영진 | …", "조직도 / …") ④ Kiwi 를 끈 경우 머리말 첫 칸의 이름 모양 값.
    이 값의 다른 곳 언급은 누락 검사로 세지 않는다.
  - 범위는 넓은 쪽으로만 바뀐다 (none < context < all). **한 run 의 문서는 두 번 거쳐 처리한다** — 전부 탐지해 토큰·범위를 정한 뒤
    전파 (`pseudonymize_documents`, `RulePseudonymizer.batch`, 노드는 `batch` 가 있으면 그걸 쓴다). 문서 A 에서 좁던 값이 문서 B 에서
    넓어져도 A 의 언급이 남지 않는다 (code review M5).
  - 롤백 주의: `local`·`context` 를 모르는 이전 코드로 되돌리면 mapping.json 의 두 필드를 무시하고 그 값들을 전부 전파한다 (code review L6).
  - 머리말 값이 본문에서 바뀐 수는 `counts["header_propagated"]` 에 남기고, 한 값이 5번 이상이면 경고 로그(토큰 id·건수만, 마지막 점검 M2).
  - batch 의 한 문서라도 누락 검사에 걸리면 통과한 문서도 쓰지 않고(앞서 쓴 것은 지움) `batch_failed` 로 돌려준다 (마지막 점검 L2).
  - 대안 비교: 공개 어휘에서 1~2음절 단어를 모두 빼면 기술 외래어 실험의 본문 과치환이 29 → 66, 공개어 회사 15개 중 문맥 없는 본문
    유지가 8 → 2 라서 고용 문맥 전파를 택했다.
- Kiwi 분석은 **줄 단위**로 한다 (문서 통째로 넣으면 줄바꿈을 넘어 "데이터⏎가온누리" → "데이터+가(조사)+온+누리"). 줄 분석 결과는
  문서 하나를 처리하는 동안만 캐시하고 버린다 (`kiwi_tools.document_cache`, code review M4).
- **회사** (`detect_org_context`) — 사전 실체가 들어 있으면 사전 규칙 몫("네이버클라우드" → "[ORG_1]클라우드"):
  1. 업종 접미어 한 단어. 어간 **전체**가 일반어 목록(`org_generic_stems.txt`)의 단어 하나일 때만 뺀다 — 끝말로 비교하면
     "…국민카드"·"…투자저축은행" 같은 실제 회사 모양이 숨는다 (privacy-auditor 2차 H2). 약한 접미어(은행·카드·전자·증권·커머스·랩·테크 …)는
     본문에서 Kiwi 가 사전 일반 명사로만 나누면 아님("추심+은행", "자동+화+솔루션"). '금융투자' 접미어 추가.
  2. 경력 머리말: 기간이 있는 100자 이하·문장 아닌 줄의 첫 칸 + 구분자 뒤 팀·직무("가상랩 | 플랫폼팀 | 2022.04 ~ 현재", 날짜가 앞이어도),
     또는 첫 단어 + 팀 이름("가상정보기술 인프라운영팀 (2023.03 ~ 현재)"). 직무로 끝나는 칸("Python개발자", "ML엔지니어")·
     영문 기술어 칸("Spring Boot")은 아님 (2차 M1).
  3. 재직 문맥: "X에서 3년간", "X 인턴/근무/재직", "X에 입사".
  접미어 없는 한 단어는 **2의 구분자 머리말 첫 칸에서만** 받고 그 칸은 항상 바꾼다: 공개 어휘가 아니면 전체 전파("다온", "누리"),
  공개 어휘면 고용 문맥 전파("중앙", "온프레미스"). 기술어 목록 단어("정산", "성과")·직무로 끝나는 칸은 회사가 아니다.
  팀 이름 앞·재직 문맥에서는 접미어 없는 한 단어를 받지 않는다. 이름 모양 후보는 회사로 보지 않는다(이름 탐지기 몫).
  경력 머리말은 100자 이하이고 문장 끝(마침표 붙은 "…다./…요.", 줄 끝 "…다/요/함/음/임")이 아닌 줄 — "이음 | …" 의 '음'은 문장 끝이 아니다.
- **교육 과정**: "… 양성 과정 / 교육·훈련·전문가·개발자 과정 / 부트캠프 / 아카데미 / 캠프 / 스쿨" + 같은 줄에 들은 사람의 말(수료·이수·수강·기수),

  끝난다고 본 단어에서 멈춘다. "인재 양성 과정을 설계", 앞말에 붙은 "교육훈련 과정", "AI 아카데미 강사로 참여"는 아님. 사전 과정이 들어 있으면 사전 몫.
- **사내 제품**: "사내·자체·자사 + 꾸밈말 0~3개 + 따옴표 이름", 따옴표 앞뒤 도구어(시스템·챗봇·봇·메신저·라이브러리 …).

  정규식). 공백·탭·점·하이픈 2만 자 줄도 탐지기 정규식은 선형이다 (code review M7). 줄을 잘라 탐지하지는 않는다 — 자른 뒤쪽 개인정보를

- 토큰 번호는 등장 순서. 실행 간에는 공유하지 않는다.

## 탐지

1. 문서 구조 기반: 인적사항 칸, 학력 칸, 경력 머리말(회사·기간) — `ingest` 가 분리한 칸 정보를 쓴다.
2. 패턴: 이메일·전화·URL·주민번호 형태 정규식.
3. 사전: 대학 목록, 회사 목록(온톨로지 `company` 포함), 성씨+이름 패턴.
4. 로컬 형태소 분석기 Kiwi [확정] — **OpenAI·OpenCode 를 포함한 외부 API 사용 금지** (가명화 전 텍스트이므로).
   외부 LLM 은 가명화를 통과한 뒤에만 쓴다 (CLAUDE.md 불변식 2).

## 누락 검사

- 치환 후 텍스트에 1~3 탐지기를 **다시** 돌려 0건이어야 통과.
- 매핑의 원 값이 치환본에 부분 문자열로 남아 있지 않은지 검사.
- 결과 `PseudoCheck{passed, residual_count, detectors}` 를 State 에 남긴다 (잔여 값 자체는 남기지 않는다).

## 타입으로 강제

```python
class PseudonymizedText(str):
    """pseudonymize 노드만 생성할 수 있다. 생성자는 모듈 private."""
```

- 구현: `schemas/pseudo_text.py` — 생성에 모듈 private 토큰 `_MINT` 필요. 만드는 곳은 `nodes/pseudonymize.py` 의
  `mint_pseudonymized()`·`load_pseudonymized()`(검사 통과본만) 뿐. 입력 스키마 필드는 `PseudoTextField` 로 선언한다.
- 가명화본이 없거나 읽을 수 없으면(경로·해시 불일치, 없는 파일·OSError, UTF-8 아님) `load_pseudonymized()` 는 모두
  `PseudonymizedNotAvailable` 하나로 낸다. 주장 텍스트를 가명화본에서 다시 만드는 곳(retrieve_t1·verify_overlap·면접 질문)은
  `load_claim_texts()` 만 쓴다 — 못 만든 주장은 빼고 `claim_not_pseudonymized`(id·고정 문구), 실행은 계속 (#246).
- `prompting.assemble()` 과 임베딩 클라이언트는 지원자 텍스트 인자를 `PseudonymizedText` 로만 받는다.
- 일반 `str` 을 넘기면 타입 검사(mypy/pyright)와 런타임 검사 둘 다에서 막힌다.

## 저장

- 가명화본: `data/pseudonymized/<run_id>/`.
- 매핑(토큰 → 원 값): `data/pseudonymized/<run_id>/mapping.json` — **State·로그·API 응답·LLM 입력에 넣지 않는다.**
  암호화 저장 여부·보존 기간 [미정].
- 명세·승인 화면은 토큰 그대로 보여 준다. 역치환이 필요한 화면은 [미정].

## 채용담당자 인터뷰 글 (#262) [확정: 2026-11-19 사용자 — 결정 4]

지원서가 아니라 채용담당자가 쓴 글(사례 대화·양식·고친 사례)과 인터뷰 맥락에 넣는 공고 줄도 LLM 전에 가명화한다.
`nodes/pseudonymize/interview.py` (`InterviewPseudonymizer`) — 지원서와 같은 탐지기(`RulePseudonymizer.detectors`, Kiwi 공유).

- 인터뷰마다 대응표 하나(`RunMapping`) — 같은 이름은 턴이 달라도 같은 토큰. 회사 이름은 표기 변형('(주)…'·'…')까지 ORG 토큰으로 먼저 넣는다.
- 비밀 값(키·비밀번호·토큰 모양)은 가명화하지 않고 거절. 잔여(누락 검사)가 있으면 거절.
- 담당자가 화면의 가명화 글을 고쳐 보내면 **대응표에 있는 토큰은 살리고**(엔진을 거치는 동안 자리표시로 감쌈), 없는 토큰 모양은 무력화.
  원 값으로 되돌려 다시 가명화하지 않는다 — 고용 문맥에서만 잡히는 회사명이 다른 문장에서 다시 안 잡혀 원문이 남는다.
- LLM 이 쓴 글(질문·사례 초안·기준 답안)과 DB 에서 다시 읽은 가명화 글은 `derived`/`stored*` — 패턴 탐지기·위조 토큰 검사만(이름 탐지기는 LLM 글에서 오탐).
  LLM 입력은 `stored_json` 이 만든 `PseudonymizedText` 만 (인터뷰 입력 스키마 칸은 `PseudoTextField`).
- 상태(DB)에는 일반 `str` 로 둔다 — `PseudonymizedText` 는 깊은 복사·검증에서 다시 만들어지지 못한다.
- 저장: DB 에는 가명화한 글만. 대응표는 `data/interviews/<id>/mapping.json`(700/600) — 과제 승인·인터뷰 폐기 때 삭제,
  방치 30일(업무 저장 기준 — 임시 저장은 활동 아님) = 폐기. 대응표는 DB 저장보다 **먼저** 쓴다(토큰은 더하기만 — DB 저장이 끊겨도 쓰지 않는 토큰만 남음).
  화면 임시 저장(원문)은 처음 쓴 때부터 최대 하루, 제출하면 바로 삭제 (`interview/service.py` sweep).
- 원문 예외: 공고 회사명·직무명(공고 표에 이미 원문), 확인자 이름(직원 식별자) — LLM 입력에는 넣지 않는다.
- 비밀 값 거절(`_SECRET`)은 붙여 넣은 자격 증명 모양만 — 라벨 뒤 ':'·'=' 가 붙은 것, 대문자 환경 변수, 토큰 형식. 평범한 문장은 통과.
- 한계: 진짜 토큰 바로 뒤에 붙인 라벨 값('담당자: [PERSON_1] 실명')은 라벨 탐지기가 건너뛸 수 있다 (탐지기는 토큰과 겹치는 구간을 버린다).

## 테스트
